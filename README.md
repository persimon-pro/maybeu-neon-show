# LOFT SHOW

Игра с шестью раундами, экраном для проектора и пультом ведущего.

## Vercel

`vercel.json` собирает статическую версию с `VITE_GAME_TRANSPORT=mqtt`. Node.js API и постоянный сервер для этой версии не нужны. После отправки изменений в связанную ветку Vercel выполняет собственную сборку и публикацию.

Откройте главную страницу и дождитесь QR-кода. «Главный экран» открывает экран игры; QR-код открывает пульт на телефоне. Для проверки в одном браузере можно открыть экран и пульт в разных вкладках. «Новая игра» создаёт отдельную комнату. Ссылка пульта содержит ключ ведущего в URL-фрагменте, который сохраняется в браузере и удаляется из адресной строки. Для зрителей используйте `/display?room=...` без ключа.

Статическая версия синхронизирует подписанные снимки состояния через `test.mosquitto.org` и `broker.emqx.io` по WSS. Получатели проверяют цифровую подпись и принадлежность открытого ключа комнате; ключ ведущего брокерам не передаётся. Состояние игры публично для знающих адрес комнаты. Неподписанные, изменённые, устаревшие и повторные снимки не применяются. Одновременная работа двух брокеров не удваивает действия или таймер. Вкладки одного браузера также обмениваются подписанными снимками через канал своей комнаты, даже без внешней сети.

Для управления с телефона нужно доступное WSS-соединение хотя бы с одним брокером. Если оба недоступны, интерфейс сообщает об ограничении; вкладки одного браузера продолжают работать. При восстановлении отправляется последний снимок, а не очередь старых команд. Доступность публичных брокеров не гарантируется. Ведите игру с одного пульта; при одновременных командах нескольких ведущих побеждает более новый снимок. Таймер вычисляется из времени запуска, поэтому количество экранов не ускоряет его; часы устройств должны быть синхронизированы. Снимки сохраняются по комнатам в браузере и как retained-сообщения брокеров. Закрытие браузера само по себе не останавливает запущенный таймер — используйте паузу.

Локальная проверка статической версии:

```sh
npm ci
VITE_GAME_TRANSPORT=mqtt npm run build:vercel
npm run preview
```

Требуется современный браузер с Web Crypto Ed25519, HTTPS (или localhost).

## Разработка с Node.js

Требуется Node.js 24 и npm.

```sh
npm ci
npm run dev
```

Без `VITE_GAME_TRANSPORT=mqtt` используется собственный Express/Socket.IO сервер на порту 3000. Главная страница создаёт комнату на сервере, QR-код передаёт ключ ведущего. Разные комнаты изолированы. Телефон должен иметь доступ к серверу; для локальной сети QR-код содержит IP компьютера.

При смене раунда таймер останавливается. В Node-режиме команды без соединения не отправляются; при отключении всех клиентов таймеры ставятся на паузу. Пустые комнаты удаляются через 24 часа. Состояние и ключи Node-режима находятся в памяти сервера: после перезапуска создайте новую игру. Несколько серверных реплик требуют общего хранилища состояния и Socket.IO adapter; текущая конфигурация рассчитана на один процесс.

## Проверки

```sh
npm run lint
npm test
npm run build
npm audit
```

Тесты проверяют границы игровых данных, таймеры, сброс игры, изоляцию серверных комнат, права ведущего, некорректные сообщения, повторное подключение, цифровые подписи и расчёт таймеров статической версии.

## Production с Node.js (альтернатива Vercel)

```sh
npm ci --include=dev
npm run build
NODE_ENV=production PORT=3000 npm start
```

Express раздаёт frontend и Socket.IO на одном порту. Dockerfile и render.yaml используют Node.js 24. Для публичного размещения используйте HTTPS и проксирование WebSocket. Gemini API key не требуется ни в одном режиме.
